# 运行时二维码赞赏

> English version: [Runtime QR Donation](../../en/features/runtime-qr-donation.md)

## 概述

页脚低调入口（☕）打开弹窗，展示在打开时由浏览器实时生成的支付宝 / 微信支付二维码——仓库无二维码图片、无后端、无第三方 API。

## 背景

「请喝咖啡」入口的常见做法要么接入托管服务（Buy Me A Coffee、Ko-fi），要么把收款码截图作为静态图片提交进仓库。托管服务引入第三方脚本、埋点与账号依赖；静态截图则让每次换收款链接都变成一次二进制资源提交，且图片质量被截图设备绑架。

## 问题

对一个零依赖、零请求的静态工具，赞赏入口不应成为唯一「向外打电话」的功能：

- 页脚承诺「无网络请求」，就不能引入第三方脚本或 iframe；
- 不应存在需要反复重新生成并提交的二维码图片；
- 手机上支付必须省力（唤起钱包 App 是常态），桌面端只能扫码；
- 不能有死胡同：手机上跳转失败时，用户仍必须能扫码完成支付。

## 目标

- 支付二维码完全在客户端由短支付串渲染。
- 支付串只在一处配置，形式就是纯字符串。
- 弹窗体验达到原生对话框水准：Esc 关闭、遮罩点击关闭、打开时焦点圈定、关闭后焦点归还、i18n 完整。
- 平台支持处为手机用户提供唤起入口；所有人始终能看到可扫的二维码。
- 二维码库的字节仅在用户真正打开弹窗时才加载。

## 非目标

- 不做后端、支付 API 集成、金额选择或交易记录——钱只在你与支付提供方之间流动。
- 不接入托管打赏服务、不引入第三方脚本。
- 不尝试经 `wxp://` 深链唤起微信（浏览器中不可靠）；微信始终只给二维码。
- 桌面端不做唤起入口——桌面没有钱包 App，展示跳转链接纯属噪音。
- 不做多档打赏、赞助者名单或动效装饰。入口始终保持为页脚一个安静的按钮。

## 方案概述

全部逻辑在一个零依赖 IIFE（`js/donation.js`）中，加上 `index.html` 的弹窗标记与 `css/donation.css` 的样式：

1. **配置：** `DONATION_CONFIG` 把每种方式（`alipay`、`wechat`）映射到一个 `qrContent` 支付串——与支付提供方分发的商户收款码 payload 相同。
2. **弹窗：** 页脚按钮打开遮罩 + 弹窗（切换 `hidden` 属性，`role="dialog" aria-modal="true"`）。焦点移到关闭按钮，Tab 在弹窗可聚焦元素间圈定，Esc / 遮罩点击 / × 关闭，焦点归还页脚入口。
3. **懒加载库：** 首次打开时以 `<script>` 标签注入 `qrcode-generator` v1.4.4（MIT，vendor 锁定，压缩后 21 KB）——一条同源请求，仅在需要时发生。
4. **SVG 二维码：** 模块以 `<rect>` 绘制在白色卡片上（纠错级别 M、4 模块静区、约 220px 目标尺寸），按方式在内存中缓存；切换语言时清空缓存，使 SVG 的 `aria-label` 以新语言重新生成。
5. **手机端跳转：** 在触屏为主的设备上，支付宝方式额外显示「打开支付宝」按钮，指向普通 `https` 链接（支付宝页面自行处理唤起）。软检测器（1.5 秒内的 visibilitychange / pagehide / blur）从不*宣称*失败——若未见跳转，只把提示文案换成「请改用扫码」。

## 详细行为

| 方面 | 行为 |
| --- | --- |
| 默认状态 | 弹窗隐藏；二维码库未加载；方式 = 支付宝 |
| 打开 | 显示遮罩 + 弹窗，`<html>` 加 `donation-open` 类（锁定滚动），焦点 → 关闭按钮，开始生成二维码 |
| 切换方式 | 更新激活按钮与 `aria-pressed`、更新提示；若已生成则缓存的二维码立即换入 |
| 关闭 | Esc、遮罩点击、弹窗背景点击或 × —— 移除监听、焦点归还页脚入口 |
| 手机 + 支付宝 | 「打开支付宝」链接可见（`href` = 普通 `https` URL）；点击后布防 1.5 秒跳转检测 |
| 未检测到跳转 | 提示变为「没有自动打开？请使用支付宝 / 微信扫码」——二维码保持可见 |
| 手机 + 微信 | 无跳转链接；仅二维码 + 「打开微信扫一扫」提示 |
| 库加载失败 | 提示变为二维码错误文案；弹窗仍可关闭 |
| 打开状态下切换语言 | 静态文案重新应用；动态提示重渲染；二维码缓存清空并重新生成（aria-label 语言） |
| 移动端判定 | UA 匹配（Android/iPhone/iPad/iPod/Mobile）**或**（多点触控 + 粗指针）——覆盖桌面式 iPad UA 而不误伤触屏笔记本 |

## 用户体验

入口是页脚的一个按钮，与「无网络请求」脚注并排、视觉上安静。弹窗是站点研报风格的纸面卡片：标题、一句请求、双方式胶囊 pill 控件、居中二维码、以及一行始终告诉你下一步做什么的提示。

## 兼容性与历史影响

该功能纯增量：页脚一个按钮、`<body>` 末尾一对遮罩 + 弹窗、首次打开时一条懒加载 `<script>`。不影响任何既有行为——除非打开弹窗，转换器绝不加载二维码库，这一点由 E2E 断言「首次打开前二维码库未加载」保证。无历史行为受影响。

## 数据与隐私影响

- **新增存储：** 无（localStorage 仍只有 `ts-lang` 一个键）。
- **新增网络：** 首次打开弹窗时一条同源脚本请求（`vendor/qrcode-generator/qrcode.min.js`）；仅当用户点击「打开支付宝」时一次外部跳转（普通 `https` 链接）。
- **支付数据：** `DONATION_CONFIG` 中的支付串是提交在仓库里的公开商户收款 payload；任何付款人信息都不会到达本项目。摘要见[隐私说明](../privacy.md)。

## 性能影响

二维码库（21 KB，约 200 个二维码模块渲染为行内 SVG）仅在首次打开弹窗时加载、每次页面加载至多一次，生成的码按方式缓存。对首屏无影响——E2E 套件断言首次打开前库不存在。

## 当前局限

- 弹窗不是原生 `<dialog>` 元素（写作时优先了更广的浏览器兼容）；焦点圈定因此为手动实现。
- 跳转检测天然只能尽力而为：浏览器不暴露外部 App 是否打开，因此设计上只软性更换提示、绝不隐藏二维码。
- 更换支付串需要编辑 `DONATION_CONFIG`（一处字符串改动）——维护者没有免部署轮换收款链接的界面。

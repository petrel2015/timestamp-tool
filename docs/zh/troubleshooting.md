# 故障排查

本应用真实的故障模式，按症状排列。英文版见 [Troubleshooting](../en/troubleshooting.md)。

若你的情况未覆盖，请[开 Issue](https://github.com/petrel2015/timestamp-tool/issues) 并附上：浏览器及版本、操作系统、你输入的确切内容（或 `?ts=` 的 URL）、用的是线上站点还是自托管、以及控制台输出。

## 输入与转换

| 症状 | 可能原因 | 修复 |
| --- | --- | --- |
| 输入框下方提示「请输入有效的数字时间戳」 | 输入包含数字、可选前导 `-`、空格 / 逗号 / 下划线之外的内容（如 `1.5e9`、`abc`、`+100`） | 使用纯数字；可接受输入表见[使用指南](./usage.md#时间戳转日期时间) |
| 提示「超出可表示的日期范围」 | 数值超出 ECMAScript 日期范围（自 1970 年约 ±273,790 年） | 该值本身无法表示为 JavaScript 日期 |
| 我确知是秒的 12 位数值被按毫秒解析 | 自动识别按位数判断（12–15 位 → 毫秒） | 点击 **秒** 单位按钮强制解释 |
| 与其他工具结果差一点 | 对方按不同单位（秒 vs 毫秒）或不同时区解释 | 对比 UTC 行而非仅本地时间；检查单位选择 |
| 日期选择器到不了公元 1 年之前 | 原生 `type="date"` 限制 | 改用（负数）时间戳输入——那里支持完整范围 |
| 时间选择器的秒位消失 | `type="time"` 配 `step="1"` 的浏览器差异 | 该栏始终接受 `HH:MM`（秒默认 `0`）；支持的浏览器中可手动输入秒 |

## 界面

| 症状 | 可能原因 | 修复 |
| --- | --- | --- |
| 复制按钮无反应（无对勾闪烁） | 嵌入式 webview 或非安全上下文中剪贴板被拒；异步 API 与 `execCommand` 兜底均失败 | 手动选择复制；自托管时请用 `https://` 或 `http://localhost` 伺服 |
| 重启后语言选择丢失 | localStorage 不可用（隐私模式 / 存储被禁） | 预期降级——选择仅本次会话有效 |
| 首次访问语言「不对」 | 检测跟随浏览器语言（`zh*` → 中文，否则英文） | 在顶栏切换一次；选择即被存储 |

## 赞赏弹窗

| 症状 | 可能原因 | 修复 |
| --- | --- | --- |
| 提示「二维码生成失败，请刷新重试」 | vendor 脚本 `vendor/qrcode-generator/qrcode.min.js` 加载失败——多为自托管时漏掉了 `vendor/` 目录 | 确保部署了完整仓库（含 `vendor/`）；刷新页面 |
| 手机上「打开支付宝」没唤起 App | 软检测触发（1.5 秒无跳转）——部分浏览器拦截外部导航 | 直接扫码；二维码全程可见（设计上没有死胡同） |
| 微信没有「唤起 App」按钮 | 有意为之：`wxp://` 深链在浏览器中不可靠 | 用微信 App 扫二维码 |

## 自托管与开发

| 症状 | 可能原因 | 修复 |
| --- | --- | --- |
| `node test/e2e-donation.js` 连接失败 | 63647 端口没有开发服务器（套件固定期望此端口） | `python3 -m http.server 63647 --directory . &` 后重跑 |
| E2E 在 `require('playwright')` / jsQR / pngjs 处失败 | 开发依赖不可解析 | 安装后导出 `NODE_PATH`，或 `npm i -D playwright pngjs jsqr`——见[开发指南](./development.md#运行-e2e-测试) |
| E2E 浏览器启动失败 | Playwright 版本与缓存 Chromium 不匹配 | 对已装的 playwright 版本执行 `npx playwright install chromium` |
| 部署后 CSS/JS 是旧版 | HTTP 缓存 | 强制刷新；检查 `index.html` 中该资源的 `?v=` 令牌是否已递增 |
